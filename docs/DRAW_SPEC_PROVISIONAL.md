**Status:** provisional. Written by Member D so the in-browser verifier and the mock server can be built before `docs/DRAW_SPEC.md` exists.
**Owner of the real spec:** Member A. When A publishes it, A's spec and vectors win. Any mismatch is a bug report to A, never a silent patch on our side.

Everything below is pinned by test vectors generated by an independent Python implementation (`frontend/tools/ref_draw.py` → `frontend/src/features/fairness/vectors.json`). If A adopts this spec as-is, those vectors can be reused directly.

## Draw (`algorithm_version: "fd-draw/1-provisional"`)

| Step | Definition |
|---|---|
| Server seed | 32 random bytes. Sent as 64 lowercase hex characters. |
| Commitment | `hex(SHA-256(server_seed_bytes))`. Published before the window opens. |
| Beacon | `{ source, round, randomness }`. The round is announced before the window. `randomness` is 32 bytes (hex), published after that round exists. |
| Weights | Only `1`, `0.5`, `0.25`. Their text form is exactly `"1"`, `"0.5"`, `"0.25"`. |
| Entrant list text | Lines `public_id + "," + weight_text`, sorted ascending by `public_id` (code point order), joined by `"\n"`, no trailing newline. An empty list gives `""`. |
| public_id | Printable ASCII, no comma or whitespace, 1 to 128 characters. |
| `entrants_hash` | `hex(SHA-256(utf8(entrant_list_text)))`. Published when the window closes. |
| `final_seed` | `SHA-256(server_seed_bytes ‖ beacon_randomness_bytes ‖ utf8(event_id) ‖ entrants_hash_bytes)`: raw bytes concatenated, the entrants hash as its 32 raw bytes (not hex text). |
| Per-entrant value | `h = HMAC-SHA256(key = final_seed_bytes, msg = utf8(public_id))`. |
| Unweighted order (all weights 1) | Ascending by `h` as a 256-bit big-endian unsigned integer. |
| Weighted order (any weight ≠ 1) | `u = (int(h) + 1) / (2^256 + 1)` and `key = -ln(u) / weight`, ascending. Computed as `(lnBig(2^256 + 1) - lnBig(int(h) + 1)) / weight`, where `lnBig(x)` = `ln(x)` if `x` has ≤ 53 bits, else `ln(x >> s) + s·ln 2` with `s = bitlength - 53`. |
| Ties | Ascending `public_id` (both modes). |
| Result | The first `min(N, count)` entrants win; the rest are waitlisted, in key order. |
| `winners_hash`, `waitlist_hash` | `hex(SHA-256(utf8(ids joined by "\n")))`. An empty list hashes `""`. |

**A note on weighted draws.** These use IEEE doubles and `ln`. JavaScript's `Math.log` and C's `log` could in theory differ in the last bit. Our 2,000-entrant weighted vector orders identically in V8 and CPython, and a tie would need two keys within one ulp. For a binding draw, A may still prefer a fixed-point formulation. The unweighted path is exact BigInt arithmetic.

### Endpoints the verifier reads (shapes are assumptions, filed as A15)

- `GET /events/{id}/fairness`: `{ event_id, phase, algorithm_version, seed_commitment, server_seed|null, beacon: { source, round, randomness|null }, entrants_hash|null, entrants_count|null, final_seed|null, inventory, result: { winners_count, waitlist_count, winners_hash, waitlist_hash }|null, audit_head_hash|null, server_now }`
- `GET /events/{id}/fairness/entrants`: `{ event_id, count, entrants: [{ public_id, weight }] }`, in canonical order. Returns 409 before the window closes.
- `GET /events/{id}/fairness/results` (optional but recommended): `{ event_id, winners: [...], waitlist: [...] }` in draw order. When present, the verifier compares entry by entry and names the first difference.

## Audit chain

| Item | Definition |
|---|---|
| Record | `{ seq, type, ts, payload, prev_hash, hash }`. `seq` starts at 1 and increases by 1. |
| Hashed bytes | `utf8(prev_hash + "\n" + canonical_json({ seq, type, ts, payload }))` |
| `hash` | `hex(SHA-256(hashed bytes))` |
| First record | `prev_hash` = 64 × `"0"` |
| `canonical_json` | Object keys sorted by Unicode code point. No whitespace. Strings escaped as `JSON.stringify` / Python `json.dumps(ensure_ascii=False)` do. Arrays keep their order. Booleans and null as JSON. Numbers must be safe integers; floats are rejected rather than given a guessed text form. |

Endpoints (assumptions, filed as A16):
- `GET /events/{id}/audit?from_seq=N&limit=M` returns `{ event_id, records, next_from_seq|null, head: { seq, hash }|null }`.
- `GET /events/{id}/audit/verify` returns `{ ok, head_seq, head_hash, checked, first_bad_seq|null }`.

The browser recomputes the whole chain, and compares its head with the server's `verify` answer and with `audit_head_hash` on the fairness page.
